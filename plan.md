# План разработки личного планировщика

План основан на `tz.md`. Код на этом этапе не пишется.

## Шаг 1. Каркас проекта и базовый интерфейс

### Готовый результат

Созданы три файла проекта:

- `index.html`
- `style.css`
- `script.js`

Страница открывается локально через `index.html` и показывает основной интерфейс на русском языке:

- верхнюю панель с названием, текущей датой, кнопкой `+`, переключателем темы и меню настроек;
- главный блок `Сегодня`;
- блок `Эта неделя`;
- блок `Просроченные`;
- блок `Планы / Идеи`;
- общий фильтр по категории и приоритету;
- пустые состояния для всех списков.

Реализованы светлая и темная темы без сохранения сложной логики задач.

### Автопроверка

Проверить:

- существуют ровно нужные файлы проекта;
- `index.html` подключает `style.css` и `script.js`;
- страница открывается без ошибок JavaScript в консоли;
- все основные блоки присутствуют в DOM;
- все основные тексты интерфейса на русском языке;
- переключение темы меняет класс/атрибут темы на странице;
- интерактивные элементы доступны с клавиатуры;
- у SVG-кнопок, если они используются, есть `aria-label` и `title`.

### Ручная проверка

Проверить глазами:

- выглядит ли интерфейс спокойно, современно и не слишком ярко;
- действительно ли блок `Сегодня` воспринимается главным;
- удобно ли расположены `Эта неделя`, `Просроченные` и `Планы / Идеи`;
- не перегружены ли карточки и верхняя панель.

## Шаг 2. Хранение данных, первый запуск и настройки

### Готовый результат

Реализована модель данных из ТЗ:

- единая сущность `Task`;
- поля `dueDate`, `time`, `myDayDate`, `category`, `priority`, `status`, `repeatRule`, `seriesId`, `order`;
- структура `localStorage` под ключом `planner:v2`;
- сохранение темы;
- первый запуск с 1-2 демо-задачами;
- сброс данных без повторного создания демо-задач;
- обработка недоступного `localStorage` с работой в памяти;
- функция миграции данных;
- автоочистка завершенных задач старше 30 дней.

### Автопроверка

Проверить:

- при пустом `localStorage` создается структура версии `2`;
- при первом запуске создаются демо-задачи;
- после перезагрузки данные сохраняются;
- после сброса создается пустая структура без демо-задач;
- тема сохраняется после перезагрузки;
- фильтры после перезагрузки сбрасываются на `all`;
- завершенные задачи старше 30 дней удаляются при старте;
- активные задачи при автоочистке не удаляются;
- при искусственной ошибке `localStorage` приложение продолжает работать в памяти и показывает предупреждение;
- `migrateData()` не удаляет неизвестные данные молча.

### Ручная проверка

Проверить:

- понятно ли выглядит предупреждение о проблеме сохранения;
- не слишком ли заметны опасные действия в настройках;
- удобно ли переключать тему.

## Шаг 3. Создание, редактирование и базовые действия с задачами

### Готовый результат

Пользователь может:

- нажать `+` и открыть форму добавления;
- быстро создать задачу только с названием;
- создать задачу с датой, временем, категорией, приоритетом и повтором;
- создать задачу без даты, которая попадет в `Планы / Идеи`;
- редактировать задачу прямо на карточке;
- выполнить задачу;
- отменить выполнение в течение 8 секунд;
- отменить задачу через статус `cancelled`;
- удалить задачу с подтверждением;
- очистить завершенные задачи с подтверждением.

Реализована валидация:

- обязательное поле только название;
- название обрезается от лишних пробелов;
- максимум 120 символов для названия;
- максимум 1000 символов для описания;
- время нельзя задать без даты срока или даты планирования;
- дата в прошлом сохраняется без предупреждения.

### Автопроверка

Проверить:

- Enter в быстром добавлении создает задачу;
- Esc закрывает форму или отменяет редактирование;
- пустое название не сохраняется;
- пробелы по краям названия удаляются;
- слишком длинные название и описание ограничиваются или показывают ошибку;
- задача только с названием попадает в `Планы / Идеи`;
- задача с `dueDate` без `myDayDate` получает `myDayDate = dueDate`;
- задача с датой в прошлом попадает в `Просроченные`;
- выполнение меняет `status` на `completed` и скрывает задачу;
- отмена выполнения за 8 секунд возвращает задачу в `active`;
- отмена задачи меняет `status` на `cancelled` и скрывает задачу;
- удаление без подтверждения не удаляет задачу;
- очистка завершенных удаляет только `completed` и `cancelled`;
- все изменения сохраняются после перезагрузки.

### Ручная проверка

Проверить:

- удобно ли добавлять задачу через кнопку `+`;
- понятна ли форма добавления;
- удобно ли редактировать прямо на карточке;
- не мешает ли уведомление `Отменить` после выполнения;
- достаточно ли понятны подтверждения удаления и очистки.

## Шаг 4. Правила отображения, сортировка, фильтры и перенос

### Готовый результат

Реализованы правила отображения:

- `Сегодня` показывает активные задачи с `myDayDate` на текущую дату;
- `Эта неделя` показывает дни с понедельника по воскресенье, включая пустые дни;
- `Просроченные` показывает задачи с `dueDate` раньше текущей даты;
- `Планы / Идеи` показывает активные задачи без `dueDate` и без `myDayDate`;
- просроченные задачи не дублируются в других блоках;
- просрочка считается по дате, а не по времени;
- задачи с временем сортируются по времени;
- задачи без времени сортируются вручную по `order`;
- общий фильтр по категории и приоритету работает для всего экрана;
- счетчики обновляются после изменений;
- ручной перенос меняет `myDayDate`, а `Изменить срок` меняет `dueDate`.

### Автопроверка

Проверить:

- задача на сегодня с прошедшим временем остается в `Сегодня`;
- задача со вчерашним `dueDate` появляется только в `Просроченные`;
- задача без даты появляется только в `Планы / Идеи`;
- задача с `myDayDate` на будущий день текущей недели появляется в нужном дне недели;
- пустые дни недели отображаются;
- задачи с временем идут в порядке `08:00`, `08:30`, `09:30`;
- задачи без времени сохраняют ручной `order`;
- фильтр `Работа + Срочно` показывает только подходящие задачи;
- после перезагрузки фильтр сбрасывается;
- счетчики сегодня, срочных сегодня, недели, просроченных и идей обновляются;
- перенос на завтра меняет `myDayDate` и не меняет `dueDate`;
- изменение срока меняет `dueDate` и может переместить задачу в `Просроченные`.

### Ручная проверка

Проверить:

- легко ли понять разницу между `Перенести` и `Изменить срок`;
- удобно ли читать неделю компактным списком;
- не мешают ли фильтры;
- хорошо ли видны метки категории и приоритета;
- понятны ли пустые состояния и мотивирующее сообщение в `Сегодня`.

## Шаг 5. Drag-and-drop, повторяющиеся задачи, импорт и экспорт

### Готовый результат

Реализованы оставшиеся продуктовые функции:

- drag-and-drop между днями недели;
- drag-and-drop в `Сегодня`;
- drag-and-drop из `Планы / Идеи` в конкретный день;
- ручная сортировка задач без времени;
- запрет нарушения хронологии задач с временем;
- повторяющиеся задачи с `seriesId`;
- создание следующего экземпляра после выполнения;
- ближайшая будущая дата для просроченных повторяющихся задач;
- выбор `Только эту` / `Всю серию` при редактировании и удалении повторяющихся задач;
- экспорт JSON;
- импорт JSON с подтверждением, проверкой структуры и миграцией.

### Автопроверка

Проверить:

- drag-and-drop между днями меняет `myDayDate`;
- drag-and-drop из идей в день задает `myDayDate`, но не назначает `time` и не заполняет `dueDate` автоматически;
- drag-and-drop задач без времени меняет и сохраняет `order`;
- задачу на `15:00` нельзя поставить выше задачи на `10:00` в группе задач с временем;
- ежедневная повторяющаяся задача после выполнения создает следующий экземпляр;
- просроченная ежедневная задача после выполнения создает ближайший будущий экземпляр, а не старую просроченную дату;
- еженедельные, будничные и ежемесячные повторы рассчитываются по правилам ТЗ;
- для даты 31 января ежемесячный повтор корректно переходит на последний день февраля;
- редактирование повторяющейся задачи спрашивает `Только эту` / `Всю серию`;
- удаление повторяющейся задачи спрашивает `Только эту` / `Всю серию`;
- экспорт создает валидный JSON;
- импорт валидного JSON заменяет данные после подтверждения;
- импорт некорректного JSON не меняет текущие данные и показывает ошибку.

### Ручная проверка

Проверить:

- удобно ли перетаскивать задачи мышкой;
- понятно ли визуальное состояние во время перетаскивания;
- не кажется ли выбор `Только эту` / `Всю серию` запутанным;
- удобно ли расположены импорт и экспорт в настройках.

## Шаг 6. Финальная проверка, устойчивость и полировка

### Готовый результат

Приложение полностью соответствует критериям готовности из `tz.md`.

Проверены:

- локальный запуск через `index.html`;
- работа без интернета;
- сохранение и восстановление данных;
- основные сценарии пользователя;
- доступность с клавиатуры;
- длинные тексты;
- 1000 задач;
- состояния hover, focus, disabled, ошибка, drag-and-drop;
- отсутствие внешних зависимостей.

### Автопроверка

Проверить:

- `index.html` открывается локально без сервера;
- в проекте нет внешних URL для скриптов, стилей, картинок и иконок;
- нет ошибок JavaScript в консоли при основных сценариях;
- данные сохраняются после перезагрузки;
- экспортированные данные можно импортировать обратно;
- приложение не ломается на 1000 задачах;
- длинные названия и описания не ломают DOM-структуру карточек;
- все кнопки доступны через Tab;
- Enter и Esc работают по ТЗ;
- фокус видим;
- все основные критерии готовности из `tz.md` пройдены.

### Ручная проверка

Проверить:

- приятно ли пользоваться приложением каждый день;
- не раздражают ли цвета в светлой и темной теме;
- достаточно ли крупный и заметный блок `Сегодня`;
- удобно ли читать карточки и неделю на ширине рабочего компьютера;
- понятны ли действия без дополнительных объяснений;
- не ощущается ли интерфейс перегруженным.
