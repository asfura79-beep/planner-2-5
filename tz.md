# Техническое задание: личный планировщик задач

Версия: 2.0 после ревью требований.

## 1. Назначение продукта

Нужно разработать личный веб-планировщик задач для одного пользователя. Продукт заменяет бумажный список дел и помогает каждый день видеть:

- что запланировано на сегодня;
- какие задачи имеют дедлайн или день выполнения в ближайшие дни;
- какие задачи просрочены;
- какие идеи пока не имеют срока;
- какие задачи относятся к работе или личным делам;
- какие задачи имеют высокий, обычный или низкий приоритет.

Главная продуктовая иерархия:

1. `Сегодня` - главный экран и главный фокус приложения.
2. `Ближайшие 7 дней` - вспомогательный обзор ближайших дедлайнов и планов без дублирования сегодняшних задач.
3. `Просроченные` - отдельный список того, что требует решения.
4. `Планы / Идеи` - задачи без даты и без планирования на конкретный день.

Приложение должно быть простой локальной веб-страницей без сервера и базы данных. Все данные хранятся в браузере через `localStorage`.

## 2. Состав проекта

Проект должен состоять из трех файлов:

- `index.html` - структура страницы;
- `style.css` - стили, темы, визуальное оформление;
- `script.js` - логика приложения, работа с задачами, сохранение в `localStorage`.

Точка входа: `index.html`.

Приложение должно открываться напрямую в браузере как локальный HTML-файл по двойному клику и полностью работать без интернета.

## 3. Технологические ограничения

Использовать чистые HTML, CSS и JavaScript без сборщиков и зависимостей.

Запрещено использовать:

- сервер;
- базу данных;
- внешние API;
- регистрацию и авторизацию;
- npm-пакеты;
- CDN;
- сторонние UI-библиотеки;
- картинки и иконки из интернета.

Разрешено:

- встроенные inline SVG-иконки прямо в HTML/CSS/JS для компактных кнопок действий;
- текстовые подписи, `aria-label` и `title` для всех кнопок с иконками;
- стандартные браузерные API для скачивания и загрузки JSON-файла резервной копии.

Причина выбора: проект должен быть переносимым, понятным, работающим офлайн и не зависящим от внешних сервисов.

## 4. Пользователь и роли

В системе есть только один пользователь - владелец планировщика.

Ролей, аккаунтов, совместного доступа, прав доступа и синхронизации между устройствами нет.

## 6. Основная структура интерфейса

Интерфейс должен быть рассчитан в первую очередь на компьютер и занимать всю ширину окна.

Рекомендуемая структура:

1. Верхняя панель:
   - название приложения;
   - текущая дата;
   - кнопка `+` для добавления задачи;
   - переключатель светлой и темной темы;
   - меню настроек с действиями `Экспорт данных`, `Импорт данных`, `Очистить завершенные`, `Сбросить все данные`.

2. Главная рабочая область:
   - крупный блок `Сегодня`;
   - более компактный блок `Ближайшие 7 дней`.

3. Вспомогательная область:
   - блок `Просроченные`;
   - блок `Планы / Идеи`.

Приложение не должно показывать обучающий экран при первом запуске. При самом первом запуске отображается обычный интерфейс с 1-2 демо-задачами. После полного сброса данных демо-задачи повторно не создаются.

## 7. Визуальный стиль

Стиль должен быть спокойным, светлым, современным, пастельным и не раздражающим глаз.

Основной вид:

- светлый фон;
- мягкие тени или тонкие границы;
- аккуратные карточки задач;
- достаточно воздуха между блоками;
- без кислотных цветов;
- без визуального шума;
- действия на карточке компактные.

Темная тема нужна в первой версии. Она должна быть спокойной, с хорошей читаемостью и без резких контрастов.

### 7.1. Цвета категорий

Категории отображаются цветными метками:

- `Работа` - спокойный голубой / серо-синий.
- `Личное` - мягкий лавандовый / шалфейный.

Архитектура данных должна позволять позже добавить новые категории, но в первой версии в интерфейсе доступны только `Работа` и `Личное`.

### 7.2. Цвета приоритета

Поле называется `Приоритет`, а не `Срочность`, чтобы не смешивать субъективную важность задачи с объективным сроком.

Значения:

- `Срочно` - приглушенный коралловый.
- `Обычно` - нейтральный серо-синий.
- `Можно позже` - мягкий зеленый.

## 8. Модель данных

В первой версии используется одна сущность `Task`. Отдельного типа `idea` нет.

Задача без `dueDate` и без `myDayDate` отображается в разделе `Планы / Идеи`.

Задача с `myDayDate` отображается в соответствующем дне планирования.

Задача с `dueDate` имеет объективный срок.

### 8.1. Поля задачи

```js
{
  "id": "task_1723800000000_ab12",
  "title": "Позвонить клиенту",
  "description": "",
  "dueDate": "2026-08-17",
  "time": "09:30",
  "myDayDate": "2026-08-17",
  "category": "work",
  "priority": "urgent",
  "status": "active",
  "completedAt": null,
  "cancelledAt": null,
  "repeatRule": "none",
  "seriesId": null,
  "order": 10,
  "createdAt": "2026-08-16T10:00:00.000Z",
  "updatedAt": "2026-08-16T10:00:00.000Z"
}
```

### 8.2. Значения полей

`dueDate`:

- дата объективного срока в формате `YYYY-MM-DD`;
- может быть `null`, если у задачи пока нет срока.

`time`:

- ориентир по времени в формате `HH:mm`;
- может быть `null`;
- не является основанием для просрочки внутри текущего дня.

`myDayDate`:

- дата, на которую пользователь запланировал выполнение задачи;
- может быть `null`;
- при создании задачи со сроком по умолчанию равна `dueDate`;
- действие `Перенести в другой день` меняет `myDayDate`, а не `dueDate`;
- действие `Изменить дедлайн` меняет `dueDate`.

`category`:

- `work` - работа;
- `personal` - личное.

`priority`:

- `urgent` - срочно;
- `normal` - обычно;
- `later` - можно позже.

`status`:

- `active` - активная задача;
- `completed` - выполненная задача;
- `cancelled` - отмененная задача.

`repeatRule`:

- `none` - не повторять;
- `daily` - каждый день;
- `weekly` - каждую неделю;
- `weekdays` - по будням;
- `monthly` - каждый месяц.

`seriesId`:

- стабильный идентификатор серии повторяющихся задач;
- одинаковый для всех экземпляров одной серии;
- для неповторяющихся задач равен `null`.

`order`:

- число для сохранения ручного порядка задач без времени внутри дня или раздела.

## 9. Структура localStorage

Данные хранятся под ключом:

```js
planner:v2
```

Структура:

```js
{
  "version": 2,
  "tasks": [],
  "settings": {
    "theme": "light",
    "filters": {
      "category": "all",
      "priority": "all"
    },
    "demoSeeded": true,
    "resetWasUsed": false
  }
}
```

Выбранные фильтры не сохраняются после перезагрузки страницы. При старте они всегда сбрасываются на `all`.

Тема сохраняется.

### 9.1. Миграции

В `script.js` должна быть функция миграции данных, например `migrateData(data)`.

Если в `localStorage` найдены данные старой версии:

1. попытаться привести их к текущей структуре;
2. если миграция невозможна, показать ошибку и предложить экспортировать сырые данные перед сбросом;
3. не удалять данные молча.

## 10. Первый запуск

При первом открытии:

- если данных нет, создать начальную структуру;
- создать 1-2 демо-задачи;
- показать обычный интерфейс без обучающих экранов.

Примеры демо-задач:

- `Проверить план на сегодня`, сегодня, без точного времени, `Личное`, `Обычно`;
- `Добавить первую рабочую задачу`, завтра, `10:00`, `Работа`, `Можно позже`.

После сброса всех данных демо-задачи не создаются повторно. Пользователь получает пустой планировщик.

## 11. Добавление задачи

Пользователь нажимает кнопку `+`.

Открывается компактная форма добавления.

Минимальный быстрый сценарий:

1. пользователь вводит только название;
2. нажимает Enter или `Сохранить`;
3. задача создается как `План / Идея`.

Поля формы:

- название - обязательно;
- описание - необязательно;
- дедлайн `dueDate` - необязательно;
- время - необязательно;
- категория - необязательно, по умолчанию `Личное`;
- приоритет - необязательно, по умолчанию `Обычно`;
- повтор - необязательно, по умолчанию `Не повторять`;
- день выполнения `myDayDate` - необязательно.

Если пользователь указал `dueDate`, но не указал `myDayDate`, система автоматически ставит `myDayDate = dueDate`.

Если пользователь указал дату в прошлом, задача сохраняется без дополнительного окна подтверждения и отображается в `Просроченные`.

Задачи с одинаковыми названиями разрешены.

## 12. Редактирование задачи

Редактирование происходит прямо на карточке задачи.

Пользователь нажимает `Редактировать`, карточка переходит в режим редактирования.

Можно изменить:

- название;
- описание;
- дедлайн;
- время;
- день выполнения в `Сегодня` / `Ближайшие 7 дней`;
- категорию;
- приоритет;
- повторяемость.

Действия:

- `Сохранить`;
- `Отмена`.

`Esc` отменяет редактирование. `Enter` сохраняет, если фокус не находится в многострочном описании.

## 13. Действия на карточке

На активной карточке должны быть доступны действия:

- `Выполнить`;
- `Отменить задачу`;
- `Редактировать`;
- `Перенести в другой день`;
- `Изменить дедлайн`;
- `Удалить`.

Фактический дизайн первой версии:

- на карточке постоянно видна основная кнопка `Выполнить`;
- остальные действия находятся в компактном меню `Еще`.

Для компактности действия могут быть реализованы через inline SVG-кнопки, но у каждой кнопки должны быть `aria-label` и `title`. При недостатке места допускается меню `Еще`.

Удаление требует подтверждения:

```text
Удалить задачу? Это действие нельзя отменить.
```

Отмена задачи переводит `status` в `cancelled` и скрывает ее из основных списков.

## 14. Выполнение и отмена выполнения

При нажатии `Выполнить`:

- `status` становится `completed`;
- записывается `completedAt`;
- задача скрывается из основных списков;
- на 8 секунд показывается ненавязчивое действие `Отменить`.

Если пользователь нажимает `Отменить` в течение 8 секунд:

- задача возвращается в `status: active`;
- `completedAt` очищается;
- задача возвращается в прежний раздел.

Отдельный постоянный список выполненных задач в первой версии не нужен.

## 15. Очистка завершенных задач

Завершенные задачи - задачи со статусом `completed` или `cancelled`.

Кнопка `Очистить завершенные` находится в меню настроек, а не в главной рабочей зоне.

При нажатии требуется подтверждение:

```text
Удалить все выполненные и отмененные задачи? Это действие нельзя отменить.
```

При старте приложения автоматически удалять завершенные задачи старше 30 дней.

Правило автоочистки:

- удалить задачи со `status: completed`, если `completedAt` старше 30 дней;
- удалить задачи со `status: cancelled`, если `cancelledAt` старше 30 дней;
- не удалять активные задачи;
- не показывать отдельное уведомление, если очистка прошла успешно.

Видимый счетчик скрытых выполненных задач не нужен.

## 16. Правила отображения

### 16.1. Сегодня

`Сегодня` - главный и самый крупный блок.

В нем отображаются активные задачи, у которых:

- `status: active`;
- `myDayDate` равна текущей локальной дате браузера;
- задача не просрочена по правилу из раздела `16.4`.

Задачи делятся на две группы:

1. `По времени` - задачи с заполненным `time`, сортируются строго по времени.
2. `Без времени` - задачи с `time: null`, сортируются вручную по `order`.

На карточке видны:

- время, если оно задано;
- название;
- категория;
- приоритет;
- дедлайн, если он отличается от дня выполнения;
- действия.

Если задач на сегодня нет:

```text
На сегодня все спокойно. Можно выдохнуть и выбрать, что хочется сделать дальше.
```

Если все задачи на сегодня выполнены:

```text
Все задачи на сегодня выполнены. Отличная работа.
```

### 16.2. Ближайшие 7 дней

Блок показывает семь следующих календарных дней, начиная с завтрашнего дня. Сегодняшние задачи в нем не дублируются, потому что для них есть крупный блок `Сегодня`.

В блоке отображаются активные задачи, у которых:

- `myDayDate` попадает в ближайшие 7 дней, кроме текущего дня;
- или `dueDate` попадает в ближайшие 7 дней, если `myDayDate` не задан;
- задача не просрочена.

Задачи группируются по дням.

Пустые дни нужно показывать.

Дни отображаются как раскрывающиеся строки. В свернутом виде пользователь видит день недели, дату и счетчик активных задач. По нажатию на строку раскрывается список задач этого дня.

У каждого дня отображается:

- название дня недели;
- дата;
- счетчик активных задач в этом дне.

Пример:

```text
Понедельник, 17 августа - 3 задачи
```

Внутри дня задачи также делятся на `По времени` и `Без времени`.

### 16.3. Планы / Идеи

В разделе отображаются активные задачи, у которых:

- `status: active`;
- `dueDate: null`;
- `myDayDate: null`.

Задачи сортируются вручную по `order`.

### 16.4. Просроченные

Просрочка определяется по дате, а не по времени.

Задача считается просроченной, если:

- `status: active`;
- `dueDate` заполнен;
- `dueDate` раньше текущей локальной даты браузера.

Время внутри текущего дня не делает задачу просроченной. Например, задача на сегодня на `09:00` в `09:01` остается в `Сегодня`, а не уходит в `Просроченные`.

Просроченная задача показывается только в `Просроченные` и не дублируется в `Сегодня` или `Ближайшие 7 дней`.

Система не меняет срок просроченной задачи автоматически.

## 17. Перенос задач

Автоматического переноса невыполненных задач на понедельник нет.

Причина: приложение не должно молча менять пользовательские сроки и превращать понедельник в свалку старых задач.

Вместо этого:

- просроченные задачи остаются в `Просроченные`;
- пользователь вручную решает, выполнить, отменить, изменить дедлайн или запланировать их на день;
- в блоке `Просроченные` можно добавить действие `Запланировать на понедельник`, которое меняет `myDayDate`, но не меняет `dueDate`;
- действие `Изменить дедлайн` меняет именно `dueDate`.

Ручной перенос через `Перенести в другой день` меняет `myDayDate`.

Пользователь может перенести задачу:

- на сегодня;
- на завтра;
- на любой ближайший день;
- на следующий понедельник;
- на произвольную дату.

## 18. Drag-and-drop

Drag-and-drop нужен в первой версии, но его область ограничена, чтобы поведение было предсказуемым.

Пользователь может:

- перетаскивать задачи между днями в блоке `Ближайшие 7 дней`;
- перетаскивать задачи в блок `Сегодня`;
- перетаскивать задачи из `Планы / Идеи` в конкретный день;
- менять порядок задач без времени внутри одного дня;
- менять порядок задач внутри `Планы / Идеи`.

После drop:

- обновляется `myDayDate`;
- для задачи без срока `dueDate` не заполняется автоматически;
- `time` не назначается автоматически;
- для задач без времени обновляется `order`;
- данные сохраняются в `localStorage`;
- интерфейс сразу перерисовывается.

Задачи с указанным временем всегда сортируются по времени. Drag-and-drop не должен позволять поставить задачу на `15:00` выше задачи на `10:00` в группе `По времени`.

## 19. Фильтры и счетчики

Нужен один общий компактный фильтр для всего экрана.

Фильтр по категории:

- `Все`;
- `Работа`;
- `Личное`.

Фильтр по приоритету:

- `Все`;
- `Срочно`;
- `Обычно`;
- `Можно позже`.

Фильтры категории и приоритета работают одновременно.

Выбранные фильтры не сохраняются после перезагрузки.

Нужно показывать счетчики:

- количество задач на сегодня;
- количество срочных задач на сегодня;
- количество задач на неделе;
- количество просроченных задач;
- количество планов / идей.

Счетчик скрытых выполненных задач не показывать.

Поиск по задачам в первой версии не нужен.

## 20. Повторяющиеся задачи

Поддерживаемые варианты:

- не повторять;
- каждый день;
- каждую неделю;
- по будням;
- каждый месяц.

Повторяющаяся задача должна иметь стабильный `seriesId`.

### 20.1. Создание ближайших экземпляров

Чтобы пользователь сразу видел повторяющиеся задачи в ближайшем плане, приложение заранее создает активные экземпляры повторяющейся задачи в пределах блока `Ближайшие 7 дней`.

Автосоздание выполняется:

- при открытии приложения;
- при создании повторяющейся задачи;
- при редактировании повторяющейся задачи.

Горизонт автосоздания ограничен ближайшими 7 днями, чтобы не раздувать `localStorage`.

Если экземпляр на нужную дату уже существует, дубль не создается.

### 20.2. Создание следующего экземпляра после выполнения

Когда пользователь выполняет повторяющуюся задачу:

- текущая задача получает `status: completed`;
- текущая задача скрывается;
- создается новая активная задача с новым `id`, если экземпляра на следующую дату еще нет;
- новая задача сохраняет `seriesId`;
- новая задача сохраняет название, описание, время, категорию, приоритет и `repeatRule`.

### 20.3. Расчет следующей даты

Если исходная задача не просрочена, следующая дата считается от ее `dueDate`.

Если исходная задача просрочена, следующая дата должна быть ближайшей будущей датой после текущей локальной даты браузера.

Пример: ежедневная задача была на 1 августа, а пользователь выполнил ее 10 августа. Следующий экземпляр создается на 11 августа, а не на 2 августа.

Правила:

- `daily` - следующий календарный день;
- `weekly` - тот же день недели через 7 дней или ближайшая будущая дата по этому правилу;
- `weekdays` - следующий рабочий день с понедельника по пятницу;
- `monthly` - тот же день следующего месяца или ближайший будущий месяц по правилу.

Если для `monthly` в следующем месяце нет такого числа, использовать последний день следующего месяца.

### 20.4. Редактирование повторяющейся задачи

Если пользователь редактирует задачу с `repeatRule !== "none"`, система должна спросить:

```text
Изменить только эту задачу или всю серию?
```

Варианты:

- `Только эту`;
- `Всю серию`;
- `Отмена`.

`Только эту`:

- меняет только выбранную задачу;
- если пользователь отключил повтор, задача получает `repeatRule: none` и `seriesId: null`.

`Всю серию`:

- применяет изменения ко всем активным задачам с тем же `seriesId`;
- влияет на новые экземпляры, которые будут создаваться после выполнения.

### 20.5. Удаление повторяющейся задачи

Если пользователь удаляет задачу из серии, система спрашивает:

```text
Удалить только эту задачу или всю серию?
```

Варианты:

- `Только эту`;
- `Всю серию`;
- `Отмена`.

`Всю серию` удаляет все активные задачи с тем же `seriesId`. Завершенные задачи серии можно оставить до автоочистки.

## 21. Валидация

Обязательное поле только одно:

- название.

Правила:

- пустое название не сохранять;
- пробелы в начале и конце названия обрезать;
- максимальная длина названия - 120 символов;
- максимальная длина описания - 1000 символов;
- одинаковые названия разрешены;
- дата в прошлом разрешена и без предупреждения попадает в `Просроченные`;
- время можно задать только вместе с датой срока или датой планирования.

Сообщения об ошибках показывать рядом с полем.

## 22. Клавиатура и доступность

Минимальные требования:

- Enter в быстром добавлении сохраняет задачу;
- Esc закрывает форму или отменяет редактирование;
- все интерактивные элементы доступны с клавиатуры;
- у всех полей есть видимые подписи;
- у всех SVG-кнопок есть `aria-label` и `title`;
- состояние фокуса заметно;
- disabled-состояния визуально понятны;
- контраст текста достаточный для чтения;
- кликабельная область кнопок не меньше 32x32 px.

## 23. Длинный текст и состояния интерфейса

Название задачи:

- максимум 120 символов;
- переносится на новую строку;
- не ломает карточку.

Описание:

- максимум 1000 символов;
- в карточке по умолчанию показываются первые 2-3 строки;
- полное описание доступно в режиме редактирования.

Нужно описать и реализовать состояния:

- пустой список;
- ошибка валидации;
- ошибка сохранения;
- hover;
- focus;
- disabled;
- перетаскивание;
- успешное выполнение с возможностью отмены.

## 24. Работа с localStorage

После любого изменения задач или настроек приложение сохраняет состояние в `localStorage`.

Если `localStorage` недоступен, переполнен или вызывает ошибку:

1. приложение продолжает работать в текущей сессии в памяти;
2. показывается предупреждение:

```text
Не удалось сохранить данные в браузере. Задачи будут доступны только до закрытия страницы.
```

3. интерфейс не ломается;
4. при следующих изменениях приложение снова пробует сохранить данные.

Приложение должно корректно работать минимум с 1000 задачами.

## 25. Экспорт и импорт данных

Так как все данные хранятся только в браузере, в первой версии нужен простой резервный механизм.

### 25.1. Экспорт

Действие `Экспорт данных` скачивает JSON-файл с текущим состоянием приложения.

Имя файла:

```text
planner-backup-YYYY-MM-DD.json
```

### 25.2. Импорт

Действие `Импорт данных` позволяет выбрать JSON-файл резервной копии.

Перед импортом обязательно показать подтверждение:

```text
Импорт заменит текущие задачи и настройки. Продолжить?
```

После подтверждения:

- проверить структуру файла;
- при необходимости выполнить миграцию;
- заменить текущие данные;
- сохранить в `localStorage`;
- перерисовать интерфейс.

Если файл некорректный, показать понятную ошибку и не менять текущие данные.

## 26. Сброс данных

Нужна функция `Сбросить все данные`.

Она находится в меню настроек и должна быть визуально второстепенной.

При нажатии обязательно показать подтверждение:

```text
Удалить все задачи и настройки? Это действие нельзя отменить.
```

После подтверждения:

- удалить данные приложения из `localStorage`;
- создать пустую структуру данных;
- не создавать демо-задачи повторно.

## 27. Темы

Нужны две темы:

- светлая;
- темная.

По умолчанию использовать светлую тему.

Выбранную тему сохранять в `localStorage`.

Тема переключается без перезагрузки страницы.

## 28. Адаптивность

Основная версия рассчитана на компьютер.

Интерфейс занимает всю ширину окна.

Минимальная целевая ширина: 1024px.

Полная мобильная адаптация не требуется, но интерфейс не должен критически ломаться при уменьшении окна. Блоки могут переходить друг под друга.

## 29. Сценарии использования

### 29.1. Пользователь быстро сохраняет мысль

Пользователь нажимает `+`, вводит название, нажимает Enter. Задача появляется в `Планы / Идеи`.

### 29.2. Пользователь создает задачу на сегодня

Пользователь нажимает `+`, вводит название, выбирает сегодня в `День выполнения`, при желании задает время, категорию и приоритет. Задача появляется в `Сегодня`.

### 29.3. Пользователь создает задачу с дедлайном

Пользователь указывает `Дедлайн`. Если дата дедлайна сегодня, задача появляется в `Сегодня`. Если дедлайн попадает в ближайшие 7 дней, задача появляется в `Ближайшие 7 дней`. Если дедлайн прошел, задача появляется в `Просроченные`.

### 29.4. Пользователь переносит задачу

Пользователь нажимает `Перенести в другой день` или перетаскивает карточку. Меняется `myDayDate`, дедлайн `dueDate` не меняется.

### 29.5. Пользователь меняет дедлайн

Пользователь нажимает `Изменить дедлайн` или редактирует поле `Дедлайн`. Меняется `dueDate`. Если новый дедлайн в прошлом, задача попадает в `Просроченные`.

### 29.6. Пользователь выполняет задачу

Пользователь нажимает `Выполнить`. Задача скрывается, появляется действие `Отменить` на 8 секунд. Если задача повторяющаяся, следующий экземпляр создается только если его еще нет среди заранее созданных ближайших повторов.

### 29.7. Пользователь отменяет задачу

Пользователь нажимает `Отменить задачу`. Задача получает `status: cancelled` и скрывается.

### 29.8. Пользователь работает с просроченными

Пользователь видит просроченные задачи отдельно и решает, что сделать: выполнить, отменить, изменить дедлайн, запланировать на день или удалить.

### 29.9. Пользователь делает резервную копию

Пользователь открывает настройки и нажимает `Экспорт данных`. Браузер скачивает JSON-файл.

### 29.10. Пользователь восстанавливает данные

Пользователь нажимает `Импорт данных`, выбирает JSON-файл, подтверждает замену текущих данных. Приложение загружает задачи и перерисовывает интерфейс.

## 30. Что не входит в первую версию

В первую версию не входит:

- авторизация;
- синхронизация между устройствами;
- база данных;
- сервер;
- мобильное приложение;
- полноценная мобильная адаптация;
- поиск;
- вложенные подзадачи;
- чек-листы;
- длительность задачи;
- уведомления браузера;
- календарная сетка месяца;
- внешние библиотеки;
- автоматическое изменение сроков просроченных задач.

## 31. Критерии готовности

Проект считается готовым, если:

- есть файлы `index.html`, `style.css`, `script.js`;
- `index.html` открывается двойным кликом в Chrome или Edge;
- приложение работает без интернета;
- интерфейс на русском языке;
- при первом запуске появляются 1-2 демо-задачи;
- после сброса данных демо-задачи не создаются повторно;
- можно быстро создать задачу только с названием;
- задача без срока и планирования попадает в `Планы / Идеи`;
- можно создать задачу с датой, временем, категорией, приоритетом и повтором;
- время необязательно;
- задачи без времени отображаются в группе `Без времени`;
- задача с датой в прошлом без предупреждения попадает в `Просроченные`;
- просрочка считается по дате, а не по времени внутри дня;
- задача на сегодня на прошедшее время остается в `Сегодня`;
- `Сегодня` является главным и самым крупным блоком;
- `Ближайшие 7 дней` показывает семь следующих календарных дней с датами;
- пустые ближайшие дни отображаются;
- задачи с временем сортируются по времени;
- задачи без времени можно сортировать вручную;
- drag-and-drop переносит задачи между днями;
- drag-and-drop не нарушает хронологию задач с временем;
- просроченные задачи показываются только в `Просроченные`;
- система не переносит просроченные задачи автоматически на понедельник;
- действие `Перенести в другой день` меняет `myDayDate`;
- действие `Изменить дедлайн` меняет `dueDate`;
- выполненные и отмененные задачи скрываются;
- после выполнения есть действие `Отменить` на 8 секунд;
- видимый счетчик выполненных задач не показывается;
- есть очистка завершенных задач с подтверждением;
- завершенные задачи старше 30 дней автоматически удаляются при старте;
- есть удаление активных задач с подтверждением;
- есть общий фильтр по категории и приоритету;
- фильтры категории и приоритета работают одновременно;
- выбранные фильтры сбрасываются после перезагрузки;
- есть светлая и темная тема;
- выбранная тема сохраняется;
- повторяющиеся задачи имеют `seriesId`;
- повторяющиеся задачи заранее создают экземпляры в пределах `Ближайшие 7 дней`;
- повторяющиеся задачи создают следующий экземпляр после выполнения;
- просроченная повторяющаяся задача после выполнения создает ближайший будущий экземпляр;
- при редактировании или удалении повторяющейся задачи система спрашивает, менять одну задачу или всю серию;
- данные сохраняются в `localStorage`;
- при недоступном `localStorage` приложение работает в памяти и показывает предупреждение;
- есть экспорт JSON;
- есть импорт JSON с подтверждением и проверкой структуры;
- есть функция миграции данных;
- приложение корректно работает минимум с 1000 задачами;
- длинные названия и описания не ломают карточки;
- интерактивные элементы доступны с клавиатуры;
- состояния hover, focus, disabled, ошибка и drag-and-drop визуально понятны;
- интерфейс занимает всю ширину окна и удобен на компьютере.
