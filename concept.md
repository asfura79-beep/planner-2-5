# Концепция проекта: личный планировщик задач

## Цель проекта

Создать личный веб-планировщик задач в виде одной страницы, состоящей из трех файлов:

- `index.html`
- `style.css`
- `script.js`

Планировщик должен работать полностью в браузере, без сервера, баз данных и внешней авторизации. Все задачи и настройки сохраняются локально через `localStorage`.

Главная задача проекта - заменить бумажный листок с задачами на спокойный, удобный и визуально понятный инструмент, где сразу видно:

- что нужно сделать сегодня;
- какие задачи срочные;
- какие задачи относятся к работе;
- какие задачи относятся к личным делам;
- что нужно сделать в течение текущей недели;
- какие задачи просрочены;
- какие задачи уже выполнены.

## Язык интерфейса

Интерфейс полностью на русском языке.

## Основная структура страницы

Страница состоит из двух главных зон:

1. **Сегодня**
   - Самый заметный и крупный блок на странице.
   - Показывает задачи, запланированные на текущий день.
   - Задачи отображаются крупнее, чем в недельном списке.
   - Срочные задачи визуально выделяются сильнее.

2. **Эта неделя**
   - Компактный список задач на ближайшие дни недели.
   - Не должен конкурировать по визуальному весу с блоком "Сегодня".
   - Нужен для понимания ближайшего горизонта без перегрузки интерфейса.

Дополнительные служебные зоны:

- **Просроченные** - задачи с прошедшим дедлайном, которые не выполнены.
- **Выполненные** - скрытый или сворачиваемый раздел для завершенных задач.
- **Форма добавления задачи** - простая и быстрая, чтобы задачу можно было занести без лишних действий.

## Модель задачи

У каждой задачи должны быть следующие поля:

- название;
- описание;
- дата выполнения;
- время или дедлайн;
- срочность;
- категория;
- статус выполнения;
- признак повторяемости.

### Срочность

Доступны три уровня срочности:

- `Срочно`
- `Обычно`
- `Можно позже`

Срочность должна быть видна прямо на карточке задачи.

### Категории

Доступны две основные категории:

- `Работа`
- `Личное`

Категории должны различаться цветными метками. Цвета должны быть спокойными, не кислотными и не раздражающими глаз.

### Повторяемость

Планировщик должен поддерживать повторяющиеся задачи.

На первом этапе можно предусмотреть простые варианты:

- не повторять;
- каждый день;
- каждую неделю;
- по будням.

Повторяемые задачи должны автоматически появляться в нужные дни, при этом не мешая обычным разовым задачам.

## Работа с задачами

Пользователь должен иметь возможность:

- быстро добавить новую задачу;
- отредактировать существующую задачу;
- изменить дату;
- изменить время или дедлайн;
- изменить срочность;
- изменить категорию;
- отметить задачу выполненной;
- вернуть задачу из выполненных при необходимости;
- удалить задачу.

Поиск по задачам на первом этапе не нужен.

## Перенос задач

Невыполненные задачи должны автоматически переноситься на следующую неделю, на понедельник.

Это правило важно для просроченных и незавершенных задач:

- если задача не выполнена в срок, она попадает в состояние просроченной;
- при переходе к следующей неделе невыполненные задачи переносятся на понедельник новой недели;
- при переносе задача не должна терять категорию, срочность, описание и время.

Также нужно предусмотреть ручной перенос задачи на другой день недели.

Перенос может быть реализован через простое меню выбора дня. Drag-and-drop не является обязательным требованием, но может быть добавлен позже, если не усложнит интерфейс.

## Фильтры

Нужны фильтры, чтобы быстро менять видимость задач.

Минимальный набор фильтров:

- все задачи;
- только рабочие;
- только личные;
- только срочные;
- только обычные;
- только "можно позже";
- просроченные;
- выполненные.

Фильтры должны быть визуально компактными и не занимать много места.

## Выполненные задачи

После отметки задачи как выполненной она должна исчезать из основного списка.

При этом задача не удаляется окончательно, а переносится в отдельный раздел "Выполненные".

Раздел "Выполненные" лучше сделать сворачиваемым, чтобы он не отвлекал от текущего планирования.

## Просроченные задачи

Просроченные задачи должны отображаться отдельно или явно выделяться.

Задача считается просроченной, если:

- дата и время дедлайна уже прошли;
- задача не отмечена как выполненная.

Просроченные задачи должны быть заметными, но не агрессивными визуально. Лучше использовать мягкий предупреждающий оттенок, например приглушенный коралловый или теплый розовый.

## Визуальный стиль

Дизайн должен быть:

- светлым;
- спокойным;
- современным;
- пастельным;
- не слишком ярким;
- удобным для работы за компьютером;
- визуально чистым, без ощущения перегруза.

Общее настроение: аккуратный личный рабочий инструмент, а не яркое приложение-мотиватор.

### Возможная палитра

Основной фон:

- теплый белый;
- очень светлый серо-молочный;
- светлый пастельный серо-зеленый или серо-голубой акцент.

Категории:

- `Работа` - спокойный голубой или серо-синий;
- `Личное` - мягкий шалфейный, лавандовый или пудровый оттенок.

Срочность:

- `Срочно` - приглушенный коралловый;
- `Обычно` - нейтральный серый или синий;
- `Можно позже` - мягкий зеленый или бежево-серый.

Важно избегать кислотных цветов, сильных контрастов, тяжелых темных фонов и визуального шума.

## Компоновка для компьютера

Основной сценарий использования - компьютер.

Адаптация под телефон на первом этапе не требуется, но верстку лучше делать так, чтобы в будущем ее можно было адаптировать.

Предпочтительная компоновка:

- слева или в верхней части - форма быстрого добавления;
- крупно по центру - задачи на сегодня;
- справа или ниже - компактный список "Эта неделя";
- ниже - сворачиваемые разделы "Просроченные" и "Выполненные".

## Хранение данных

Все данные хранятся в `localStorage`.

Нужно предусмотреть структуру данных, например:

```js
{
  tasks: [
    {
      id: "уникальный-id",
      title: "Название задачи",
      description: "Описание",
      date: "2026-08-16",
      time: "18:00",
      urgency: "urgent",
      category: "work",
      completed: false,
      repeat: "none",
      createdAt: "2026-08-16T10:00:00.000Z",
      updatedAt: "2026-08-16T10:00:00.000Z"
    }
  ],
  settings: {
    activeFilter: "all"
  }
}
```

Экспорт и импорт данных на первом этапе не нужны.

## Ограничения

Проект должен быть сделан без:

- серверов;
- баз данных;
- регистрации;
- внешних API;
- сборщиков;
- сложных зависимостей;
- поиска по задачам;
- обязательной мобильной адаптации;
- экспорта и импорта.

Страница должна открываться локально в браузере и сохранять данные между открытиями через `localStorage`.

## Первый этап разработки

В первой версии нужно реализовать:

- базовую HTML-структуру страницы;
- спокойный светлый интерфейс;
- добавление задач;
- редактирование задач;
- удаление задач;
- отметку задач выполненными;
- разделы "Сегодня" и "Эта неделя";
- отображение просроченных задач;
- скрытый или сворачиваемый раздел выполненных задач;
- фильтры по категории и срочности;
- сохранение задач в `localStorage`;
- ручной перенос задачи на другой день;
- автоматический перенос невыполненных задач на понедельник следующей недели.

## Возможные улучшения позже

После первой рабочей версии можно добавить:

- drag-and-drop перенос задач между днями;
- более гибкие правила повторяемости;
- недельный календарь;
- статистику выполненных задач;
- резервное копирование;
- легкую адаптацию под телефон;
- переключение между несколькими мягкими цветовыми темами.
